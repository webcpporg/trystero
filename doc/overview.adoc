[#trystero-overview]
== Overview

trystero lets programs meet in a _room_ and exchange messages directly, peer
to peer, over WebRTC data channels. There is no server of the application's
own: peers find each other by publishing short signed messages on public
https://github.com/nostr-protocol/nips/blob/master/01.md[Nostr] relays,
exchange the WebRTC offer and answer through them, and from then on talk
over the connection the browser or the network stack established.

It ports the protocol of https://github.com/dmotz/trystero[Trystero] 0.26.0,
and keeps its wire byte for byte. A room joined from {cpp} and the same room
joined from Trystero's JavaScript are one room: the peers see each other, and
an action sent from one side arrives on the other.

The library provides:

* `room`, which joins a room of an application over Nostr relays, reports
  the peers that join and leave, measures round trips, and leaves with
  Trystero's farewell;
* `action<T>`, a named channel of messages: text, JSON
  (`boost::json::value`), binary, or any of the three, with optional JSON
  metadata, of any size, sent inline or in chunks with backpressure;
* the password of a room, part of the key that seals the signaling and a
  challenge added to the handshake;
* every asynchronous operation as an Asio initiating function, so it
  completes with a callback, `boost::asio::use_awaitable`,
  `boost::asio::deferred` or any other completion token;
* a memory resource per room, which every allocation of the room goes
  through (<<trystero-allocation>>);
* a backend interface that separates the room from the platform, and its
  two implementations, for the browser and for native programs.

[#trystero-overview-targets]
=== Two backends

`<webcpp/trystero.hpp>` is the rooms themselves, which build on both of
trystero's targets, native and emscripten, and include neither backend.
Each backend is a header of its own:

[cols="1,1,3",options="header"]
|===
| Backend | Target | Built on

| `<webcpp/trystero/browser/backend.hpp>`
| emscripten
| the page's `WebSocket`, `RTCPeerConnection`, `RTCDataChannel`,
  `setTimeout` and `crypto.subtle`, through embind (<<trystero-browser>>)

| `<webcpp/trystero/native/backend.hpp>`
| native
| libdatachannel for WebRTC, Boost.Beast for the relays' WebSockets,
  OpenSSL for TLS and AES-GCM, and Asio's timers (<<trystero-native>>)
|===

Both run the same room, and both meet Trystero JS peers. Every name is in the
namespace `webcpp::trystero`.

[#trystero-overview-requirements]
=== Requirements

* A {cpp}20 compiler.
* Boost 1.92: Asio, Container (its `pmr` base class), Core, Hash2, JSON and
  System; and Beast for the native backend.
* https://github.com/bitcoin-core/secp256k1[libsecp256k1] 0.8.0, with its
  `schnorrsig` and `extrakeys` modules, for the BIP-340 signatures of Nostr
  events: every room needs it.
* In the browser: Emscripten 6.0.11, the version webcpp pins, and a page
  served from a secure context (https, or http on `localhost`), where
  `crypto.subtle` exists.
* Natively:
  https://github.com/paullouisageneau/libdatachannel[libdatachannel] 0.24.6
  and OpenSSL 3, and exceptions (<<trystero-native-exceptions>>).

trystero raises no exception of its own: an operation that can fail
completes with an error code. The rooms, the protocol and the browser
backend compile without exceptions; so do the native timer, sealer and
WebSockets.
