[#trystero-overview]
== Overview

trystero lets programs meet in a _room_ and exchange messages directly, peer
to peer, over WebRTC data channels. There is no server of the application's
own: peers find each other by publishing short signed messages on public
https://github.com/nostr-protocol/nips/blob/master/01.md[Nostr] relays,
exchange the WebRTC offer and answer through them, and from then on talk
over the connection the browser or the network stack established.

It ports the protocol of https://github.com/dmotz/trystero[Trystero] 0.27.0,
and keeps its wire byte for byte: a room joined from {cpp} and the same room
joined from Trystero's JavaScript are one room. The peers verify each
other's identities with Trystero's signed handshake, see each other, and an
action sent from one side arrives on the other.

The library provides:

* `room`, which joins a room of an application over Nostr relays, admits
  each peer once its signed handshake verified its endpoint and its user,
  holds at most `max_users` users, reports the peers and users that join
  and leave, and the problems it handled, to listeners that each return a
  subscription, measures round trips, and leaves with Trystero's farewell;
* `action<T>`, a named channel of messages: text, JSON
  (webcpp::document's), binary, or any of the three, with optional JSON
  metadata, of any size, sent inline or in chunks with backpressure, to
  peers or users, with a receive gate and progress; and
  `request_action<T, R>`, whose requests a peer answers;
* one immutable password per app, from which every room derives its keys
  off the room's thread; separate passwords use separate apps and ids;
* every asynchronous operation as an Asio initiating function, so it
  completes with a callback, `webcpp::asio::use_awaitable`,
  `webcpp::asio::deferred` or any other completion token of webcpp::asio,
  which natively is Boost.Asio itself;
* an `app` per program in one application and password domain, with one
  endpoint identity, its peer id, and one user identity, ephemeral or a
  `user_identity` the program creates, exports and imports as 0.27.0 does;
  each of its rooms negotiates its own connection to each remote peer;
* a resource for the app and an optional resource for each room, which
  receive their allocations (<<trystero-allocation>>);
* a backend interface that separates the room from the platform, and the
  platform backend, one implementation of it for native programs and for
  pages, whose WebRTC is webcpp::webrtc's on both.

[#trystero-overview-targets]
=== Two targets, one backend

`<webcpp/trystero.hpp>` is the rooms themselves, which build on both of
trystero's targets, native and emscripten, and leave the platform backend
out. The backend is a header of its own, beside a page's:

[cols="1,1,3",options="header"]
|===
| Header | Target | What it holds

| `<webcpp/trystero/platform/backend.hpp>`
| native and emscripten
| `platform::backend`: webcpp::webrtc for WebRTC, natively over
  libdatachannel and in a page over its `RTCPeerConnection` and
  `RTCDataChannel`; webcpp::beast for the relays' WebSockets, natively
  Boost.Beast's and in a page its `WebSocket`, their URLs read with
  Boost.URL; webcpp::asio's timers; webcpp::crypto's `random_device`; and
  the PBKDF2 of a room's password, webcpp::hash's, natively on a thread of
  its own and in a page through `crypto.subtle` (<<trystero-platform>>)

| `<webcpp/trystero/platform/page.hpp>`
| emscripten
| `platform::page_call` and `platform::js_string`, what a page's program
  uses beside the backend (<<trystero-platform-page>>)
|===

The backend runs the same room on both targets, and meets Trystero JS peers
on both. Every name is in the namespace `webcpp::trystero`.

[#trystero-overview-requirements]
=== Requirements

* A {cpp}20 compiler.
* Boost 1.92: Asio, Assert, Charconv and JSON (whose definitions
  webcpp::document links, its parser and its numbers), Circular Buffer,
  Container (its `pmr` base class), Endian, Hash2, System and Unordered for
  the rooms; URL for the platform backend's relays, and Beast for them
  natively.
* webcpp::document for every JSON text, webcpp::asio, webcpp::hash for the
  digests, HMAC, HKDF and PBKDF2 of the room keys, webcpp::crypto for
  AES-256-GCM, randomness, the ECDSA P-256 signatures of identities and
  handshakes, over BearSSL, and the BIP-340 signatures of Nostr events, over
  https://github.com/bitcoin-core/secp256k1[libsecp256k1] 0.8.0, both of
  which webcpp builds from their pinned sources, and webcpp::webrtc and
  webcpp::beast
  for the platform backend's WebRTC and relays (<<trystero-building>>).
* In the browser: Emscripten 6.0.11, the version webcpp pins, and a program
  whose `main` runs its `io_context` (<<trystero-platform-run>>); a room
  with a password also needs a page served from a secure context (https,
  or http on `localhost`), where `crypto.subtle` exists for its PBKDF2.
* Natively:
  https://github.com/paullouisageneau/libdatachannel[libdatachannel] 0.24.6,
  through webcpp::webrtc, and OpenSSL 3.

trystero raises no exception of its own: an operation that can fail
completes with an error code. Every part of it, the platform backend
included, compiles and works without exceptions
(<<trystero-platform-exceptions>>).
